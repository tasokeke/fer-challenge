# fer-challenge

ჩვენი მიზანი იყო, რომ შეგვესრულებინა Kaggle-ის Challenges in Representation Learning: Facial Expression Recognition Challenge და ნეირონული ქსელების გამოყენებით დაგვეტრენინგებინა მოდელი, რომელიც შეძლებდა და მოცემული 7 ემოციიდან (Angry, Disgust, Fear, Happy, Sad, Surprise, Neutral) სურათზე გამოსახულ ემოციას ამოიცნობდა. 
PyTorch ფრეიმვორკის გამოყენებით ავაგეთ სხვადასხვა ნეირონული ქსელის არქიტექტურა, დავტესტეთ თითოეულისთვის სხვადასხვა პარამეტრი, ჩავატარეთ განსხვავებული ექსპერიმენტები, რათა მოდელის ეფექტურობა გაგვეზარდა. 
ყველა ექსპერიმენტი დალოგილია და ორგანიზებულია Weights & Biases (WandB)-ზე, სადაც თითოეულ ნოუთბუქს აქვს შესაბამისი არქიტექტურის ჯგუფი და თითოეულში გვაქვს სხვადასხვა პარამეტრით განსხვავებული ექსპერიმენტები.

### **00_eda.ipynb**

მინიმალური და მაქსიმალური მნიშვნელობები ადასტურებს, რომ მონაცემები სუფთაა და მოთავსებულია სტანდარტულ 8-ბიტიან დიაპაზონში (0-255) ყოველგვარი ანომალიების გარეშე. გამოთვლილი Mean (129.47) და Std (65.03) არის ძალიან მნიშვნელოვანი ფაქტორი, რადგან მათ პირდაპირ ვიყენებთ PyTorch-ის მონაცემთა მომზადებისას transforms.Normalize-ში. პიქსელების ამ კონკრეტულ ციფრებზე სტანდარტიზაციით ჩვენ ნეირონულ ქსელს ვაწვდით მონაცემებს, რომლებსაც აქვთ 0-თან მიახლოებული საშუალო და 1-ის ტოლი ვარიაცია. ეს მკვეთრად აჩქარებს მოდელის კონვერგენციას (სწავლის სიჩქარეს) და იცავს გრადიენტებს აფეთქებისგან (Exploding Gradients) ტრენინგის დროს. 


პირველი მოდელი, რომელსაც დავატრენინგებთ არის simple CNN, ანუ უბრალოდ ბეისლეინ მოდელი. 

### **01_simpleCNN.ipynb**

როგორც ვთქვით, მონაცემები გაიყო Kaggle-ის ორიგინალური სტრუქტურის მიხედვით `Usage` სვეტზე დაყრდნობით: სატრენინგო ნაკრები (28,709 სურათი), ვალიდაციის ნაკრები (3,589 სურათი) და სატესტო ნაკრები (3,589 სურათი).

PyTorch-ის `EmotionDataset`-ში პიქსელების მნიშვნელობები `0-255` დიაპაზონიდან გარდავქმენით `[0, 1]` მასშტაბში (`pixels / 255.0`) და დავამატეთ ერთარხიანი (Grayscale) განზომილება `(1, 48, 48)`. მონაცემები მოდელს მიეწოდება 64-იანი ბეტჩებით (Batch Size = 64).

ავაგეთ მარტივი საკონვოლუციო ქსელი `SimpleCNN`, რომელიც შედგება:   
• `Conv2d` (1 -> 32 არხი, Kernel = 3, Padding = 1) + ReLU + MaxPool2d (2x2)   
• `Conv2d` (32 -> 64 არხი, Kernel = 3, Padding = 1) + ReLU + MaxPool2d (2x2)   
• `Linear` (Fully Connected შრე: 64 * 12 * 12 -> 128 ნეირონი) + ReLU   
• `Linear` (გამომავალი კლასიფიკატორი: 128 -> 7 კლასი)

**ვალიდაციის ტესტები (Sanity Checks):** 

ტრენინგის დაწყებამდე ჩავატარეთ მოდელის სისწორის ორი კრიტიკული შემოწმება: 
1. *Forward Check:* პირველივე ბეტჩზე მოდელის საწყისმა Loss-მა აჩვენა `1.9296`. ეს იდეალურად პასუხობს თეორიულ მოლოდინს ($\ln(7) \approx 1.9459$), რაც იმას ნიშნავს, რომ მოდელის წონები სწორად არის ინიციალიზებული და საწყის ეტაპზე ემოციებს შემთხვევითობის პრინციპით ვარაუდობს. 

2. *Backward Check (Overfit a Single Batch):* მოდელი ვავარჯიშეთ მხოლოდ ერთ კონკრეტულ ბეტჩზე 300 ბიჯის განმავლობაში. მოდელმა Loss წარმატებით ჩამოიყვანა `0.0000`-ზე, ხოლო სიზუსტე ავიდა `1.000`-ზე (100%). ეს ადასტურებს, რომ Forward და Backward პროცესები მუშაობს გამართულად, გრადიენტები სწორად ითვლება და კოდში პროგრამული ხარვეზი არ არსებობს.

**ექსპერიმენტის მიმდინარეობა და შედეგები (W&B Run: `01_SimpleCNN_Baseline`):** 

მოდელი დატრენინგდა 30 ეპოქის განმავლობაში `Adam` ოპტიმიზატორით (Learning Rate = 0.001) და `CrossEntropyLoss` ფუნქციით. ექსპერიმენტმა აჩვენა გამოკვეთილი დინამიკა:   
• მე-5 ეპოქაზე: Train Acc: 55.84% | Val Acc: 51.77%   
• მე-15 ეპოქაზე: Train Acc: 86.51% | Val Acc: 51.66% (Val Loss უკვე იწყებს ზრდას: 1.8842)   
• მე-30 ეპოქაზე: Train Acc: **97.73%** | Val Acc: **51.13%** (Val Loss გაიზარდა **4.0047**-მდე)   

• მაქსიმალური მიღწეული სიზუსტე ვალიდაციაზე (Best Val Accuracy): **53.39%** (მე-8 ეპოქაზე).

ეს ექსპერიმენტი არის **Overfitting-ის** კლასიკური მაგალითი. სატრენინგო ნაკრებზე მოდელმა თითქმის 100%-იანი სიზუსტე აჩვენა (Loss: 0.0783), რაც იმას ნიშნავს, რომ არქიტექტურას აქვს საკმარისი ტევადობა (Capacity) მონაცემების დასასწავლად. თუმცა, რეგულარიზაციის მექანიზმების (Dropout, Weight Decay) არარსებობისა და მონაცემთა სიმცირის გამო, ქსელმა უბრალოდ "დაიზუთხა" სატრენინგო სურათები. ვალიდაციის ნაკრებზე Loss-ის მკვეთრი ზრდა და სიზუსტის 53%-ზე გაჩერება მიუთითებს იმაზე, რომ მოდელმა სრულიად დაკარგა გენერალიზაციის უნარი.

ამ პრობლემის გადასაჭრელად, მომდევნო ექსპერიმენტებში (`02_deepCNN.ipynb`) აუცილებელია ქსელის სიღრმის გაზრდა ფიჩერების უკეთ დასაჭერად და რეგულარიზაციისთვის `Dropout`-ისა და `Weighted Random Sampler`-ის შემოტანა, რათა მოდელმა overfitting-ის გარეშე მოგვცეს კარგი შედეგი.

### **03_ResNet.ipynb**

პირველი, რასაც ვაკეთებთ არის სურათების ტრანსფორმაცია და აუგმენტაცია (Transforms)

აქ პირველ რიგში ხდება სურათების "მოდერნიზაცია" და ხელოვნური გამრავლება, რათა მოდელმა უკეთესად ისწავლოს:

* **ზომის შეცვლა (Resize):** მონაცემებში არსებულ 48x48 სურათებს ვზრდით **224x224**-მდე. ეს აუცილებელია, რადგან ისეთ მოდელებს, როგორიც ResNet-ია სწორედ ამ ზომის შეყვანა (input) სჭირდებათ.
* **არხების გათამაშება (Grayscale to 3 channels):** ჩვენი სურათები ერთარხიანია (შავ-თეთრი), მაგრამ ResNet-ი ელოდება სამარხიან (RGB) ფერად სურათებს. ამიტომ, ამ ფუნქციით ერთ არხს სამჯერ ვაკოპირებთ, რომ ფორმატი დაემთხვეს.
* **მონაცემთა აუგმენტაცია (Data Augmentation):** მხოლოდ სატრენინგო მონაცემებს (train) შემთხვევითობის პრინციპით ჰორიზონტალურად ტრაილდება (Flip) და მაქსიმუმ 10 გრადუსით ეცვლება კუთხეც (Rotation). ეს მოდელს ეხმარება, რომ ზეპირად არ ისწავლოს სურათები (თავიდან ავიცილებთ ოვერფიტინგის) და უფრო მდგრადი გახდეს სხვადასხვა რაკურსის მიმართ.
* **ნორმალიზაცია:** ვიყენებთ ImageNet-ის სტანდარტულ საშუალო (mean) და გადახრის (std) მაჩვენებლებს, რადგან მოდელი, რომელსაც იყენებ, თავიდანვე ამ სტანდარტით იყო ნავარჯიშები.


შემდეგ ვაგვარებთ კლასების დისბალანსს (WeightedRandomSampler-ით)

ვიცით, რომ ემოციები არათანაბრადაა განაწილებული, მოდელი რომ მხოლოდ პოპულარულ კლასებზე არ "გაიწვრთნას" ამ შემთხვევეაში:

* ვითვლით თითოეული კლასის რაოდენობას და ვიღებთ მათ საპირისპირო წონებს (იშვიათ კლასს ენიჭება დიდი წონა, ხშირ კლასს — პატარა).
* `WeightedRandomSampler` ამ წონების მიხედვით აკომპლექტებს ბათჩებს (batches). შედეგად, ტრენინგის დროს მოდელი იშვიათ სურათებს უფრო ხშირად ნახულობს, ვიდრე ჩვეულებრივ ნახავდა. ეს აბალანსებს სწავლის პროცესს.

და საბოლოოდ ვიყენებთ ტრანსფერ ლერნინგს: ResNet18 არქიტექტურა

იმის ნაცვლად, რომ ნულიდან ავაწტოთ მოდელი, გამოვიყენეთ **ResNet18**-ს, რომელიც უკვე ნავარჯიშებია ძალიან ბევრ სხვადასხვა სურათზე (ImageNet-ზე). მას უკვე აქვს "თვალები", რითაც ხედავს ფორმებს, ხაზებსა და კონტურებს.

* **Freeze Backbone:** კოდში გვაქვს ოფცია `freeze_backbone`. თუ მას ჩავრთავთ (True), ResNet-ის ძირითად ნაწილს "გავყინავთ" (არ შეცვლით ანუ მის ნასწავლ წონებს) და მხოლოდ ჩვენს დამატებულ ბოლო ფენას დავტრენინგებთ. თუ გამოვრთავთ (False), მთლიან მოდელს თავიდან გადავავარჯიშებთ (Fine-tuning).
* **FC Layer:** ResNet-ის ორიგინალ ბოლო ფენას (რომელიც 1000 კლასზე იყო გათვლილი) ვაგდებთ და მის ადგილას ვსავმთთ Dropout-ს, რომელიც წვრთნისას შემთხვევით თიშავს ნეირონების 50%-ს გათიშავს და ოვერფიტინგთან ბრძოლისთვის გამოგვადგება და ახალ linear ფენას ჩავურთავთ, რომელიც მოდელის გამოსავალს ჩვენს 7 ემოციაზე გადაანაწილებს.

როგროც ადრე აქაც გავაკეთეთ Sanity Checks

* **Forward Check:** ვამოწმებთ, სწორად ითვლის თუ არა მოდელი საწყის დანაკარგს (Loss). ვინაიდან 7 კლასი გვაქვს და მოდელი ჯერ უცნობია, შემთხვევითი ალბათობით საწყისი Loss უნდა იყოს 7-ის ნატურალური ლოგარითმის (~1.94) ტოლი. თუ კოდმა აჩვენა, რომ სხვაობა მცირეა, ე.ი. არქიტექტურა და Loss ფუნქცია სწორად მუშაობს.
* **Backward Check (უკუსვლა / იმიტირებული ტრენინგი):** ვიღებთ მონაცემების მხოლოდ **ერთ ბათჩს (სულ 64 სურათს)** და მოდელს ვაიძულებთ, რომ 200-ჯერ იტრიალოს მხოლოდ ამ 64 სურათზე.
